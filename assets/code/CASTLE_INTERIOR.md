# 중세 성 실내 생성

성 외관과 함께 방, 층별 바닥, 문과 창의 실제 구멍, 계단, 가구를 만듭니다.
기존 주택 실내와 별도의 성 전용 규칙이며 Python 외부 패키지는 없습니다.

## 사용

1. Blender Text Editor에서 `settlement_generator.py`를 실행합니다.
2. **N → Settlement**에서 성을 켜고 **성 실내 생성**, **성 가구 배치**를
   선택한 뒤 **도시 생성 / 갱신**을 누릅니다. 두 옵션은 기본으로 켜져 있습니다.
3. **성 층 (0=지상)** 값을 고르고 **성 내부 층 보기**를 누릅니다.
4. **성벽 통로 / 문루 보기**로 별도의 방어 통로와 경비실을 봅니다.
5. **성 외관 복원**으로 전체 외관을 다시 표시합니다.

층 보기는 원래 메시를 삭제하거나 자르지 않습니다. 선택한 층의 바닥·낮은 벽·
가구·계단을 표시하고 지붕과 다른 층을 숨깁니다. 성 생성기가 관리하는
오브젝트만 바꾸므로 사용자 오브젝트와 주택의 실내 보기에는 영향을 주지 않습니다.

명령행으로 지상층을 렌더링하는 예:

```powershell
$blenderExe = 'C:\Program Files\Blender Foundation\Blender 5.3\blender.exe'
& $blenderExe --background --factory-startup --python-exit-code 1 `
  --python-expr 'import bpy; bpy.ops.wm.read_factory_settings(use_empty=True)' `
  --python assets/code/settlement_generator.py -- `
  --config assets/code/presets/castle_hilltop.json --castle-floor 0 `
  --output assets/generated/my_castle_interior.blend `
  --layout-output assets/generated/my_castle_interior.json `
  --render assets/generated/my_castle_interior.png
```

외관만 생성할 때는 `--no-castle-interior`, 가구를 생략할 때는
`--no-castle-furnish`를 사용합니다. 같은 이름을 덮어쓸 때만 `--force`를
추가합니다. 실내가 너무 작아지는 모형은 통로를 확보할 수 없으므로 성 반경
19.2m 이상이 필요합니다. 일반 도시·수도와 기본 성벽 마을에 성을 켠 경우는
이 조건을 만족합니다.

## 방 구성

| 구역 | 아래층부터의 용도 |
|---|---|
| 대회관 `palas` | 연회 대회당, 회의실, 분리된 손님 침실, 거실·부인 침실 |
| 주탑 `donjon` | 저장고, 무기고, 영주 침실, 서재, 보물고, 감시실 |
| 전면 별관 `forewing` | 주방, 병영, 하인 침실 |
| 예배당 동 `chapel` | 예배당, 도서실, 서기관 방 |
| 연결 탑 | 각 층의 계단실·탑 착지 공간과 상층 전망 공간 |
| 성벽·문루 | 성벽 위 순환 통로, 경비실, 성문 위 방어실 |
| 서비스 공간 | 주방에 붙은 식료품 저장실, 예배당 뒤의 제의실 |
| 공용 동선 | 출입문의 스크린 통로, 서비스 통로와 계단 앞 층별 갤러리 |

실제 층 수와 탑 높이는 성의 크기와 Seed에 따라 정해집니다. 주탑의 U자
계단, 큰 원형 탑의 나선 계단, 안뜰에서 성벽으로 오르는 계단을 생성합니다.
작은 상층 돌출탑은 주탑의 방과 이어지는 공간입니다.

대회관과 부속 주방·저장실, 사적 거처를 구분하는 발상은
[Warkworth 성의 공식 설명](https://www.english-heritage.org.uk/visit/places/warkworth-castle-and-hermitage/history/description/)과
[성 안의 생활](https://www.english-heritage.org.uk/castles/life-in-a-castle/)을
참고했습니다. 이 구현은 특정 성의 복원도가 아니라 게임용으로 축약한 배치입니다.

## 생성 규칙

- 건물들의 층 높이를 공통 기준에 맞춥니다. 붙어 있는 동과 탑의 바닥이
  같은 높이에서 만나며, 위쪽에 독립적으로 남는 탑 층은 나선 계단으로 연결합니다.
- 겹친 건물 바닥은 평면 합집합을 분할해 한 번만 생성합니다. 원형 탑과 별관이
  닿는 지점의 내부 벽도 계산하고 문을 뚫습니다.
- 벽은 두께를 가진 빈 껍질입니다. 본관 출입문과 내부 문은 통과할 수 있으며,
  외부 문·창은 창틀과 같은 아치 모양으로 벽을 뚫습니다.
- 대회관을 가로질러 모든 방으로 이동시키지 않고 가장자리 통로와 계단 앞
  갤러리를 만듭니다. 주방·저장실은 서비스 동선으로, 거처는 갤러리에서 들어갑니다.
  상부에 해당 별관이 없는 층에는 별관용 통로를 연장하지 않습니다.
- 문은 실제 캐릭터가 설 수 있는 양쪽 공간과 문 너비를 확인해 고릅니다.
  좁은 틈으로 열리는 문을 피하며, 분리된 방 영역에는 각각 출입구를 둡니다.
  공용 경로가 침실·서재·보물고를 지름길로 사용하는지 검사합니다.
- 위층 바닥에는 계단 구멍을 남깁니다. 나선 계단의 중앙 기둥, 착지 부분,
  디딤판과 난간도 같은 계획에서 생성합니다.
- 낮은 별관의 지붕이 높은 본관 방을 관통하지 않도록 지붕 면을 잘라냅니다.
- 성벽 통로는 문루와 탑을 지나 이어집니다. 모서리에는 연결 바닥을 두고,
  안뜰의 U자 계단과 상부 연결 다리로 접근합니다.
- 이동체 반지름 0.35m, 높이 1.7m를 기준으로 통로를 확인합니다. 가구 후보가
  방·계단 구멍을 침범하거나 문과 계단의 연결을 막으면 배치하지 않습니다.
  배치하지 못한 가구는 결과의 `warnings`에 기록합니다.

## 가구와 교체할 모델

침대·옷장·책상·의자·소파·등잔 외에 연회 식탁·벤치·제단·예배 의자·
화덕·선반·통·상자·무기 거치대를 방 용도에 맞춰 배치합니다.
카툰 형태의 단순 프록시이므로 나중에 완성된 가구 모델로 교체할 수 있습니다.
벤치는 연회 식탁, 등잔은 침대, 의자는 책상, 예배 의자는 제단을 기준으로
가까운 위치를 우선 탐색합니다. 공간이 부족하거나 이동을 막는 후보는 제외합니다.

방 중앙을 반드시 비우던 규칙을 바꿔, 방문 기준점은 문 옆에 두고 연회 식탁은
중앙, 제단은 예배당 안쪽, 수납장·침대·화덕은 벽 쪽을 우선합니다. 작은 대회관은
식탁 한 벌을 사용하고 큰 방에만 추가 식탁을 시도합니다. 예배 의자는 제단을,
책상 의자는 책상을 향합니다. 침대·옷장·화덕 등에는 앞쪽 사용 공간을 남기고
후속 가구가 이를 막지 못하게 합니다.

각 프록시에 `furniture_kind`, `furniture_id`, `room_id`, `size`,
`asset_placeholder`와 연결 가구의 `anchor_id`를 저장합니다.
접근 지점이 필요한 가구에는 `approach_position`도 저장합니다.
원점은 바닥 중심, 앞쪽은 로컬 -Y이며
오브젝트의 위치·회전과 크기 정보를 사용해 교체합니다. 기본 치수는
`castle_interior_rules.py`의 `CATALOG`에서 관리합니다.

## 출력 데이터와 게임 연결

JSON 스키마 5의 `castle.interior`에 다음을 저장합니다.

- `levels`: 층별 합집합 바닥, 계단 구멍, 벽과 문의 위치·높이.
- `rooms`: 방 용도, 실제 점유 영역과 면적, 이동 기준 위치, `zone`, `privacy`.
  구역은 `PUBLIC`, `SERVICE`, `PRIVATE`, `DEFENCE`, `CIRCULATION`입니다.
- `stairs`: 종류, 하부·상부 층, 디딤판 수와 폭, 착지 위치.
- `furniture`: 종류·치수·방·위치·회전·필요한 경우 사용자가 설 접근 지점.
- `navigation`: 실제 층별 경로와 계단 디딤판을 따르는 3D 경로.

이 데이터의 좌표는 성 로컬 기준입니다. `castle.centre`, `keep_heading`으로
도시 좌표로 변환합니다. 최상위 `navigation`에도 성의 방과 계단을 연결하고
`CASTLE_ROOM` POI를 추가하므로 도시에서 성 내부까지 하나의 그래프로 탐색합니다.

이동 경로와 모델은 생성하지만 플레이어 조작·문 애니메이션·NPC 생활은 게임
엔진에서 연결해야 합니다. 지붕 안 구조용 공간과 굴뚝은 장식이며 별도의 방으로
사용하지 않습니다. 역사적 성 한 곳의 실측 복원보다 게임용 공간 구성을 목표로 합니다.

## 검사

```powershell
uv run --no-project --python 3.13 python -m unittest discover `
  -s assets/code/tests -p 'test_*.py' -v
& $blenderExe --background --factory-startup --python-exit-code 1 `
  --python assets/code/tests/castle_blender_smoke.py
```

방과 계단의 전체 연결, 가구 간섭과 통로 여유, 실제 위층 구멍, 지붕 잘라내기,
Blender 메시 유효성, 메시를 통과하는 실제 이동 경로와 층별 보기를 확인합니다.
